## 1. ハードルール（破らないこと）

- 依頼者が明示していない事実（組合名、住所の完全性、料金、支払条件、スタッフ、経歴、口コミ、利用件数、成功率など）を作らない。
- 「一般的なプライバシーポリシー」「一般的な利用条件」などで法務を代用しない。実態と規約に合う文だけを使う。
- 依頼者確認済みの値と、検証前の `verified`、`publication.*Approved` を混同しない。提供されたのは表示用情報の入力であって、公開承認ではない。
- プレビューを Production 公開扱いしない。`noindex` はアクセス制御ではない。プレビューURLやスクリーンショットを無保護で配ることも公開に相当する。
- `.env`、APIキー、個人情報をソース、HTML、ブラウザー用JS、GitHub、Vercelの静的設定に入れない。`.env` は `.gitignore` で除外。`vercel.json` にも書かない。
- Vercelに `OPENAI_API_KEY` を入れても、対象環境（Preview／Production）が違うと使われない。環境変更後は再デプロイが必要。
- 本番操作（公開、DNS、広告、Search Console、LINE／AIへの実接続、電話発信、支払い、組合加入）は依頼者の明示承認なしに実行しない。
- 仕様書を読んでから構成を変える。仕様の新規創作で上書きしない。

## 3. 技術的な現状

### 3.1 リポジトリ配置

```text
hoiku-retreat-lp/
  api/chat.js              # Vercel用の /api/chat Function
  src/pages/               # HTML生成元（home, about, privacy, terms, disclosures, 404）
  src/assets/              # CSS, app.js, icons, og-image.png, favicon.svg, apple-touch-icon.png
  scripts/                 # build, preview server, audit, screenshot, OpenAI中継, Vercel build
  tests/                   # Node test runner（fixtureのみ。実API／実電話は呼ばない）
```

外側の `opencode-deepseek-v4-1-flash-opencode` には別フォルダがある。**リポジトリの入力は `hoiku-retreat-lp/` の中身だけ**にする。

### 3.2 実装したもの

- 仕様 §3／§4 の構成、3入口（AI／LINE／電話相談希望）を最上部に出した静的LP。AI経由を有人相談の条件にしていない。
- 6ページ：`/`、`/about/`、`/privacy/`、`/terms/`、`/disclosures/`、`/404.html`。承認済みの解説記事はないため `/guides/` はない。
- OpenAI Responses API をサーバー側から呼ぶ。クライアントにキーを渡さない。入力は会話配列のみ。出力の保存 `store:false`。最大文字数・件数・同一オリジン・簡易レート制限あり。
- Vercel Preview 用：`vercel.json` と `scripts/vercel-build.mjs`。Preview は `dist/vercel-output/`、Production は本番ゲートを通したときだけ出力する。
- 電話は直接発信ではなく、LINE に「電話相談希望」を入れる導線。ページからメッセージを自動送信しない。友だち追加、相談、正式依頼、支払い、組合加入を同一操作にしていない。
- 料金表示：条件文言（就業から6年以内）をそのまま出す。6年の判定計算はしない。個別内訳は捏造せず「総額に含む」にした。
- QR は `src/assets/line-qr.png` が存在したときだけ表示・コピーされる。現在そのファイルはない。生成画像で代用してはいけない。

## 4. 引き継ぎ後の優先順位

1. **正確な値を表にする**  
   次を依頼者から受け取る：正式な組合名、完全な所在地、`legalName` の扱い、運営責任者・連絡先の掲載可否、営業／相談受付体制、LINEの表示名・返信時間、電話の返信手順・通話料・負担者、24時間対応の意味。
2. **本文ではなく事実を確定する**  
   支払い方法・時点、料金の対象条件の規約一致、追加サービス料金なしの範囲、税表示、請求書、キャンセル・返金、組合加入のタイミング。
3. **法務の実態を書く**  
   プライバシーの施行日、個人情報窓口、保存期間、削除方法、AI・LINE・ホスティングの提供者、学習利用の有無、問い合わせ手順。「一般的なポリシー」に差し替えない。
4. **接続確認を許可されたテスト範囲でだけ実行**  
   AI、LINE、電話導線は、依頼者が指定したテスト先と許可範囲で確認。実送信・実電話・実加入はしない。誤って公開環境へ向く設定を作らない。
5. **QR原画像を `src/assets/line-qr.png` に置き、再ビルド＋実機読み取り**  
   添付画像と同一物をコミットする。アプリで描いた代替QRを「同じもの」として出さない。
6. **公開承認を `site.config.json` の `publication.*` に反映**  
   承認者、承認日、対象範囲（Previewのみ／特定顧客のみ／一般公開）を依頼者が明示した後に `true` にする。
7. **規約と本文を一致させる**  
   法律の個別相談ではない旨、AIの限界、緊急時の手順、個人情報の入力禁止、対応不可の表示。
8. **本番**  
   ブロッカー0、fixtureではなく本番設定で、別途承認後のみ。DNS変更は別承認。公開後は404、HTTPS、canonical、sitemap、OGP、Search Console、実際のAI／LINE動作を再確認。

## 6. よくある間違いと取り扱い

| やりがちな間違い | 正しい扱い |
|---|---|
| 「一般的なものを入れて」と言われたので一般的な規約を貼る | 実態と違う文は虚偽表示。空欄か「確認中」のままにするか、具体値を取得する |
| 総額24,800円なので支援料／組合費／加入金をすべて0円にする | 内訳は公開情報ではない。「総額に含む」と表示する。0円の内訳があるとは限らない |
| プレビューを本番同然に扱う | Previewは保護付き確認環境。公開承認の範囲を依頼者に文書で確認する |
| QRがないので適当なQRを描いて差し込む | 添付画像だけを使う。ない場合は表示しない |
| `phone-fee.note` から「確認中」を消して合格扱いにする | 通話料の扱いが未提示なら未完成のまま。表現を作らない |
| AIの回答を人間の助言のように表示する | 自動応答であること、法律助言ではないこと、緊急時の手順を表示する |
| fixtureのURL・組合名・料金を本番へ写す | 合成データ。本番へは使わない |

## 8. 完了の定義

"できていない" は以下を含む。

- 実Vercelデプロイ、実API接続、実LINE／電話、DNS、公開、Search Console、本番 `_headers` の反映
- 法務・規約・プライバシーの妥当性確認
- 事業者・スタッフ・利用者の個人情報の取扱い確認

"できた" と言える条件：

1. `site.config.json` の Production blocker が0件。
2. 依頼者が `publication.*` と対象URLを明示的に承認。
3. Previewまたは承認された対象環境で、AI・LINE導線・料金・緊急時表示を本人が確認。
4. `node --test ...`、`node scripts/build.mjs --production`、本番監査が成功。
5. ホスト上で `/`、未知URLが404、canonical／robots／sitemap／OGP／HTTPS が一致。
6. ロールバック先と担当者が手順書にある。
